## 一句话定义

**Atolla 是一个在你自己电脑上运行的「数字员工」平台。** 你可以把本机已经登录好的 Claude Code、Codex CLI 或 Cursor Agent 包装成有姓名、岗位、工作区、权限和技能的数字员工，让它们在你授权的目录里干活；遇到写文件、联网、删除等有风险的操作，先问你，再执行。

> [!NOTE]
> 本文档基于 Atolla **v0.6.5** 编写，所有能力描述均来自产品源码与内置产品手册。

## Atolla 不是什么

为了避免误解，先说清楚边界：

| 常见误解 | 实际情况 |
| --- | --- |
| Atolla 内置了一个大模型 | **不内置模型。** 数字员工调用的是你电脑上已登录的 Claude Code、Codex CLI 或 Cursor Agent。 |
| Atolla 会替我购买或管理引擎订阅 | 不会。引擎账号、订阅与额度属于你自己，Atolla 只读取用量用于展示。 |
| 数字员工跑在云端 | 不是。引擎进程与工作区始终在你自己的电脑上，远程中继只负责转发与缓存。 |
| 手机端是另一套独立系统 | 不是。手机通过中继读取和操作的是**同一台电脑上的同一批员工与对话**。 |

## 核心概念

在后续章节中会反复出现以下术语：

| 概念 | 说明 |
| --- | --- |
| **数字员工** | 一个被包装过的本机 AI 引擎：有姓名、岗位、像素水母头像、工作区、权限策略与已安装技能。 |
| **工作引擎** | 数字员工背后的 CLI：`claude`（Claude Code）、`codex`（Codex CLI）或 `agent`（Cursor Agent）。 |
| **工作区** | 员工执行任务的默认目录。可限制员工只能在该目录内读写。 |
| **对话** | 每位员工都有自己的对话，可以有多个线程；对话通过 SSE 流式展示执行过程。 |
| **权限网关** | 所有工具动作的统一闸口，按固定顺序给出 允许 / 拒绝 / 人工复核。 |
| **实例** | 一台运行 Atolla 的电脑。手机通过实例地址与六位绑定密码与之建立关系。 |
| **远程中继** | 部署在你自己服务器上的轻量服务，让手机可以随时查看并继续电脑上的工作。 |

## 产品形态

Atolla 由几个协同工作的部分组成：

- **桌面端**：Electron 桌面应用，自动启动内置的 Go 后端，并复用同一套 React 工作台。当前提供 macOS Apple 芯片版本。
- **本机后端**：Go（Gin）服务，负责员工管理、引擎适配、权限网关、任务队列与数据持久化（默认 SQLite）。
- **远程中继**：Node.js + TypeScript + SQLite 的轻量服务，部署在你自己的服务器上。
- **移动端**：iOS App，支持查看员工、继续对话、处理审批，以及 iOS 灵动岛（Live Activity）。
- **macOS 灵动岛**：一个独立的 SwiftUI 常驻胶囊，在桌面顶部展示员工状态。

想了解它们如何协同，请阅读 [1.3 核心架构与设计理念](/docs/1-3-architecture)。
