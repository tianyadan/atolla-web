## 双层会话记忆

Atolla 把**可见消息**与**引擎原生上下文**分开保存：

| 层 | 存储位置 | 作用 |
| --- | --- | --- |
| 平台消息 | Atolla 数据库 | 恢复时间线、工具状态与审计记录 |
| 引擎 Session | 引擎自身（以 `engine_session_id` 关联） | 后续提问时延续引擎自己的原生上下文 |

```text
用户发送消息 → 保存用户内容与附件
        ↓
携带 engine_session_id 调用工作引擎
        ↓
引擎原生 Session 继续上下文
        ↓
流式事件写回消息与工具记录 → 下次打开时恢复时间线并继续 Session
```

> [!NOTE]
> 数据库历史是界面恢复的来源，但不等于完整复制了引擎内部的上下文；更换工作引擎也不能直接复用另一种引擎的 Session ID。

## 上下文压缩

当上下文接近引擎窗口上限时，可以手动或由平台触发压缩：

1. 优先调用引擎**原生 Compact**，在保留当前 Session 的前提下压缩内部记忆；
2. 收到压缩成功事件后，重置用量估算，并裁剪平台侧冗余历史；
3. 后续请求会**重新注入**系统规则、员工策略与挂载记忆摘要。

压缩是有损摘要，不保证逐字保留早期细节——关键事实建议写入任务或文件。原生压缩失败时不会假装成功，也不会清空现有 Session。

## 离职记忆与继承

解聘员工时，可以把它的重要经验整理成一本**只读记忆书**：

```text
发起解聘 → 生成离职记忆（Markdown）
        ↓
generating → ready / failed
        ↓
记忆书架：查看、编辑或重试
        ↓
由另一名员工认领 → 创建只读挂载
        ↓
后续任务注入精简记忆摘要
```

- 一份记忆只能被**一名员工**认领；
- 认领**不会恢复**来源员工的 Session、工作区文件、技能或权限；
- 记忆生成只提取你选择的信息类型，不应包含凭据、密钥或未授权数据；
- 生成失败需要显式重试，不会以空记忆冒充成功。

## 流程记忆

[流程编排](/docs/3-3-collaboration) 中的 Agent 节点结束后，会把职责、产物与决策摘要写入该员工的记忆；日常对话时，平台按相关性召回少量摘要注入提示词，而不是把完整的流程对话并入日常历史。

## 记忆边界

记忆沿**实例 → 员工 → 会话**三层隔离：

- 查询以实体 ID 组合约束，不以显示名称推断归属；
- 员工之间默认**不共享**完整历史，群聊与显式挂载也只开放各自约定的数据；
- 找不到原对象时返回明确引导，不静默切换；
- 回退到数据库消息可以恢复可见时间线，但无法重建已经丢失的引擎原生 Session。
