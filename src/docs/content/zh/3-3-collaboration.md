## 三种协作方式

Atolla 提供三种由浅入深的多员工协作方式：

| 方式 | 适合场景 | 执行方式 | 时间线 |
| --- | --- | --- | --- |
| `@` 委托 | 一次性会签、快速征求意见 | 被点名员工**并行**执行 | 结果写回发起人的对话 |
| 群聊 | 多角色持续讨论 | 群主主持，成员**串行**发言 | 群内共享一条时间线 |
| 流程编排 | 可复用的多步骤项目流程 | 可视化 DAG，支持并行与人工审核 | 每个节点独立会话 |

## @ 委托

在当前员工的输入框中使用 `@` 点名其他员工，平台会：

```text
输入 @员工A @员工B + 任务
        ↓
解析点名对象与正文 → 校验员工可用状态和权限
        ↓
分别构造委托上下文 → 并行执行
        ↓
子结果写回当前对话时间线 → 发起人继续总结或追问
```

- 点名按**员工 ID** 而不是显示名称解析；
- 每位被点名的员工仍使用**自己的引擎、工作区和权限**；
- 某位员工忙碌、离线或权限不足时会返回单独的失败状态，不影响其他人的结果；
- `@` 不会合并不同员工的引擎 Session，也不会共享对方未授权的完整历史。

## 群聊

把 **3 至 5 名**员工放入一个群聊，由群主主持首轮发言：

1. 选择成员后生成群聊，创建共享对话；
2. 群主给出议题与发言顺序；
3. 成员依次被调用，每条发言实时写入共享时间线；
4. 你可以继续提问、`@` 点名成员、设置标签或转让群主。

> [!TIP]
> 串行发言可以避免多名员工同时写入造成顺序混乱。群聊时间线**不会覆盖**成员各自的一对一对话，转让群主、修改标签只对当前群生效。

## 流程编排

流程编排（任务计划）用可视化画布把员工串成一个可重复运行的流程：

| 节点类型 | 作用 |
| --- | --- |
| Start | 输入本次任务文案 |
| Agent | 引用一位现有员工执行，节点拥有独立会话 |
| Parallel / Merge | 并行扇出；合并节点等待所有前置成功 |
| Condition | 基于上游输出的表达式分支（`==`、`!=`、`>=`、`contains`、`and` / `or`） |
| Human Review | 运行进入等待，由你通过、驳回或终止 |
| End | 流程结束 |

运行规则：

- 节点直接引用现有员工，**不复制配置**；Agent 节点复用同一套执行、权限与审计链路；
- **一名员工同一时间只占用一个主任务**，被占用时会显示忙碌来源；
- 驳回会从指定节点开启**新一轮尝试**（attempt 递增，不覆盖历史）；
- 失败后可以从失败节点重试：仍有效的前置不重跑，并行只重试失败分支；
- 服务重启时未完成的运行会标记为 `interrupted`，与失败、停止区分；
- 节点结束后会写入员工记忆，日常对话时可被召回。
