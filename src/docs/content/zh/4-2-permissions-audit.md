## 权限模型分层

Atolla 的安全判断由多层组成，每一层都**独立生效**：

| 层级 | 决定者 | 能否被覆盖 |
| --- | --- | --- |
| Hard Deny | 平台底线 | **不能**——会话授权、自动审核与人工操作都无法覆盖 |
| 员工策略 | 员工的写入 / 联网 / 删除 / 工作区开关 | 只能通过修改员工配置改变 |
| 安全只读规则 | 平台静态规则 | — |
| 会话授权 | 你在本会话中的「本次会话允许」 | 仅匹配完全相同的规范化命令签名 |
| JEV 自动审核 | 本机风险评分服务 | 异常时降级为人工审批 |
| 人工审批 | 你 | 拒绝、仅本次、本次会话 |

> [!IMPORTANT]
> 开启自动审核**不会扩大**员工原有权限，也不会绕过 Hard Deny。ALLOW 只针对当前这条规范化动作，不代表授予操作系统管理员权限。

## 命令审计

每一次权限判断都会写入命令审计（`command_audits`）：

| 字段 | 内容 |
| --- | --- |
| 动作 | 工具与命令摘要、动作类型 |
| 上下文 | 实例、员工、会话、引擎、环境与时间 |
| 结论 | ALLOW / DENY / REVIEW 及原因 |
| 决定者 | Hard Deny、员工策略、会话授权、JEV 或用户 |
| 风险 | JEV 等给出的风险分 |

审计页面提供分页与筛选，便于追溯。审计记录用于追溯，**不包含完整凭据**，界面与日志会对敏感值脱敏。

## 网络白名单

需要联网的员工可以配置**域名白名单**：

```text
网络请求 → 规范化域名 → 匹配白名单 → 同步到引擎沙箱规则
```

白名单在设置层维护，并在引擎启动或配置变化时生成对应的网络约束，让平台权限、引擎沙箱与你看到的策略保持一致。

> [!NOTE]
> 白名单是允许范围，不保证目标网站可用、可信或内容安全；DNS、代理和引擎自身的沙箱能力也可能影响实际联网结果。

## 中断审计

任务被终止时，平台会记录终止动作，并在时间线中保留已产生的内容与最终状态。Stop 只保证发送中断信号，已由外部命令产生的副作用不会自动回滚。

## 推荐的安全实践

1. 默认开启「限制工作区」，只给员工必要的目录；
2. 写入、联网、删除按岗位最小化开启；
3. 对生产资源单独登记、单独授权；
4. 公网中继务必配置 TLS，并妥善保管门禁密码与 `RELAY_JWT_SECRET`；
5. 定期在审计页回看高风险命令与决定者。
