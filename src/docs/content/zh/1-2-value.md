## 痛点：订阅了多家 AI，反而更难用

越来越多的开发者同时订阅了 Claude、Codex 和 Cursor。每一家都很强，但一起用时问题就来了：

- **来回切换**：三个终端、三个窗口，每次都要想「这个任务在哪个窗口里」。
- **上下文割裂**：不同工具之间互不认识，换个工具就得重新交代背景。
- **难以管理**：谁在跑、谁卡住了、谁在等你授权，只能挨个窗口去看。
- **离开电脑就失控**：长任务跑到一半需要授权，人不在电脑前，任务就停在那里。

## Atolla 的回答

### 1. 一个入口，统一调度三家引擎

Atolla 目前支持 Claude Code、Codex CLI、Cursor Agent 三种主流引擎。每位数字员工绑定一种引擎，平台把不同 CLI 的输出统一成同一种事件流——**不用切换平台，不用来回查看中断。** 详见 [3.1 多引擎统一编排](/docs/3-1-multi-engine)。

### 2. 高度自定义的智能体

为员工设置岗位、人设、工作区、权限策略，再从技能商店为它安装技能，就能打造跨引擎、高度定制化的 Agent 团队。详见 [3.2 数字员工、像素水母与技能商店](/docs/3-2-agents)。

### 3. 安全优先的执行模型

所有工具动作都经过权限网关：平台底线（Hard Deny）不可绕过，员工权限独立生效，无法安全自动判断的操作一律交给你审批。详见 [3.5 远程审批与安全护栏](/docs/3-5-approval)。

### 4. 随时随地掌控

把远程中继部署到你自己的服务器，手机就能查看员工状态、继续对话、处理审批；iOS 灵动岛和 Bark 通知让你不必一直盯着屏幕。详见 [3.4 跨端同步与自托管中继](/docs/3-4-relay)。

### 5. 数据属于你

引擎、工作区和平台数据都在你的电脑上；中继由你自己部署，只保存按实例分片的缓存镜像与指令信箱。详见 [4.1 数据本地化与自托管中继安全模型](/docs/4-1-data-security)。

## 价值一览

| 维度 | 没有 Atolla | 使用 Atolla |
| --- | --- | --- |
| 引擎使用 | 多个终端来回切换 | 一个工作台统一调度 |
| 任务组织 | 零散的会话 | 有岗位、有分组的数字员工团队 |
| 多人协作 | 手动复制粘贴 | `@` 委托、群聊、可视化流程编排 |
| 风险控制 | 依赖各工具自身设置 | 统一权限网关 + 人工审批 + 审计 |
| 离开电脑 | 任务停摆 | 手机审批、灵动岛与 Bark 通知 |
| 数据位置 | 分散在各工具中 | 本机为准，中继自托管 |
