## 为什么需要中继

你的电脑通常没有公网 IP，手机无法直接访问它。远程中继是一台**由你自己部署**的轻量服务器：电脑主动连接中继，手机也连接中继，双方借此通信。服务器永远不会主动连接你的电脑。

想先了解完整原理，可以阅读 [3.4 跨端同步与自托管中继](/docs/3-4-relay)。

## 准备工作

| 项目 | 说明 |
| --- | --- |
| 一台 Linux 服务器 | 可通过 SSH 登录；部署脚本会在缺少时自动安装 Node.js 20 与编译工具 |
| 一个可访问的端口 | 默认监听 `3080`，需要在防火墙 / 安全组中放行 |
| 网站门禁密码 | 部署时设置，手机登录中继站点时使用 |
| 域名与证书（可选） | 不强制 HTTPS；公网环境建议自行配置反向代理与 TLS |

## 第一步：一键部署中继

在 Atolla 的「**远程中继**」页面打开部署向导，填写：

1. 服务器地址、SSH 端口与用户；
2. 远程目录（默认 `/opt/atolla-remote-relay`）与监听端口（默认 `3080`）；
3. 网站门禁初始密码；
4. 下载源：官方源或 **China Mirror**（国内网络可加速 Node 与 npm 下载）。

向导会依次完成：SSH 连接与端口检查 → 上传中继代码 → 安装依赖并构建 → 安装 systemd 服务 → 访问 `/api/health` 健康检查 → 回写中继地址。整个过程会持续显示阶段日志；超时后保留日志并支持重试。

> [!NOTE]
> 门禁密码会以 bcrypt 哈希保存，首次启动后即从进程环境变量中清除。

如果你是开发者并持有源码，也可以直接运行同一个部署脚本：

```bash
remote-relay/deploy/install.sh \
  --host 203.0.113.10 --user root \
  --port 3080 --site-password '你的门禁密码' \
  --china-mirror
```

部署完成后可以验证：

```bash
curl http://你的服务器:3080/api/health
```

## 第二步：电脑注册为实例

部署成功后，Atolla 会把这台电脑作为一个**实例**注册到中继：

- 首次创建时生成随机的 `instance_id`，并在重启后保持不变；
- 电脑本地生成**六位绑定密码**（数字 + 英文字母），注册到中继——密码只在电脑上生成，服务器只接收与校验；
- 之后电脑通过心跳维持在线状态。

## 第三步：手机绑定

1. 在手机上打开中继站点或 Atolla iOS App，输入门禁密码登录；
2. 添加实例：填写实例地址与电脑上显示的六位绑定密码；
3. 中继校验通过后签发**独立的设备会话**，你就能看到这台电脑上的数字员工了。

> [!WARNING]
> 六位密码是短期绑定凭据，不要把它当作长期 Token 保存或分享。你可以随时在电脑上轮换密码，轮换后旧密码立即失效。

## 局域网直连（Beta）

在同一 Wi-Fi 或 iPhone 个人热点下，iPhone 还可以直接连接电脑：

- 在「远程中继」页开启局域网直连，用 iPhone 扫描电脑上的配对二维码；
- 连接策略可选「自动（局域网优先，失败回退云端）」「仅局域网」「仅云端」；
- 局域网模式使用 HTTP 加签名认证，**内容不加密，仅适用于可信网络**。

## 常见问题

| 现象 | 排查方向 |
| --- | --- |
| 健康检查失败 | 检查防火墙 / 安全组是否放行端口，服务是否在运行 |
| 手机显示实例离线 | 电脑是否开机、Atolla 是否在运行、电脑能否访问中继地址 |
| 绑定密码被拒绝 | 密码是否已轮换或过期；登录失败过多会被临时限速 |
| SSH 成功但无法访问 | SSH 成功不代表域名、证书、防火墙和公网端口都已配置正确 |
