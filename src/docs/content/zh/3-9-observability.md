## 概览

离开当前对话后，你仍然需要知道「谁完成了、谁在等我、谁出错了」。Atolla 提供四种观测方式：

| 方式 | 平台 | 适合 |
| --- | --- | --- |
| Bark 通知 | iPhone（Bark App） | 任务完成、待审批、报错时推送提醒 |
| iOS 灵动岛 | iPhone | 在锁屏与灵动岛上查看最高优先级状态 |
| macOS 灵动岛 | Mac | 桌面顶部常驻胶囊，展开查看员工与步骤 |
| 审计与运行健康 | 管理台 | 排查任务耗时、工具调用与主机资源 |

## 四态优先级

PC、移动端、中继与两个灵动岛共用同一套状态优先级：

**报错 > 待审批 > 运行中 > 已完成**

任务结束后，平台为每位员工保留**最新一条终态未读快照**（类型、时间、耗时与摘要），进入对应对话或点击事件后清除。已读只清除提醒，不删除消息、结果或审计记录。

## Bark 通知

1. 在设置中填写 Bark 地址，平台会发送**六位验证码**；
2. 验证成功后，按需开启「完成 / 待审批 / 报错」通知；
3. 通知标题标明 Atolla 与事件类型，正文包含员工名称与必要摘要，并可携带深链。

- 你正在查看对应员工时，会抑制重复提醒；
- 队列连跑时只在最终收口时通知一次；
- 通知正文不会发送完整命令 JSON、凭据或敏感日志。

## iOS 灵动岛

- 收缩态显示状态符号，展开态最多展示三行摘要；
- 运行态可以携带任务规划步骤，终态显示员工、部门、耗时与完成时间；
- 点击会恢复实例登录并跳转到对应员工对话或具体审批，深链打开后仍需通过设备会话校验。

> [!NOTE]
> 当前尚未接入 APNs Live Activity 远程推送：App 在前台和短时后台会尽力更新，被系统彻底挂起后不保证实时。

## macOS 灵动岛

macOS 灵动岛是一个独立的 SwiftUI 常驻程序：

- 管理台同步 Token 与 API 地址后，它会常驻轮询本机事件；
- 收缩 / 展开动画展示员工、运行步骤、耗时与错误摘要；
- 点击员工或审批行，打开管理台对应位置并补拉最新状态；
- 它不是苹果系统的 Live Activity，需要保持本机常驻进程运行。

## 审计与运行健康

```text
任务开始记录时间 → SSE 接收文本 / 工具 / 用量 / 规划事件
        ↓
任务终态记录耗时与摘要 → 命令决定写入审计
        ↓
实例心跳上报 CPU / 内存 / 磁盘 / 版本 → 健康页联合排查
```

这些信息帮助你区分：是员工逻辑问题、引擎问题、电脑资源不足，还是中继断线。后台守护开关与 `/health` 接口用于确认 Atolla 服务是否持续运行。
