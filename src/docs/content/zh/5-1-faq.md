## 安装与平台

### Intel 芯片的 Mac 能用吗？

当前安装包是 `Atolla-0.6.5-mac-arm64.dmg`，**仅支持 Apple 芯片**，Intel Mac 无法安装。

### 打开时提示「无法验证开发者」？

当前版本尚未签名与公证。请在「应用程序」中右键点击 Atolla → 打开，或执行：

```bash
xattr -dr com.apple.quarantine /Applications/Atolla.app
```

### 支持 Windows 和 Linux 吗？

正在开发中，详见 [5.2 平台支持与演进路线](/docs/5-2-roadmap)。

## 引擎与费用

### Atolla 收取模型费用吗？

Atolla 不内置模型，也不代购订阅。数字员工调用的是你本机已登录的 Claude Code、Codex CLI 或 Cursor Agent，费用与额度由你在各引擎服务商处的账号决定。

### 引擎检测通过了，任务还是中断？

检测通过只代表命令可以找到。请在「设置 → 工作引擎」查看用量窗口，判断是否是订阅额度、网络或凭据问题。

### 能把一个员工从 Claude 换成 Codex 吗？

可以修改员工的引擎，但原引擎的 Session 不会转换成新引擎的 Session，新的对话会从新引擎的会话开始。

## 中继与手机

### 必须部署中继吗？

不是必须。只在电脑上使用时不需要中继；想用手机查看、继续对话或审批时才需要。

### 中继会看到我的代码吗？

中继只保存移动端需要的镜像数据（员工摘要、任务状态、结构化消息），**不会同步本机文件系统和完整引擎日志**。而且中继部署在你自己的服务器上。

### 电脑关机了，手机还能派任务吗？

可以投递，但任务会留在指令信箱里，等电脑上线后才执行。手机会明确显示该实例离线。

### 一定要 HTTPS 吗？

不强制，但在公网使用时强烈建议通过反向代理配置 TLS。见 [4.1 数据本地化与自托管中继安全模型](/docs/4-1-data-security)。

## 审批与安全

### 不在电脑前，审批会超时自动通过吗？

**不会。** 页面关闭或审批超时都不会自动允许，服务端按安全默认值结束等待。

### 「本次会话允许」会放行所有类似命令吗？

不会。会话授权只匹配**完全相同**的规范化命令签名，不是通配符。

### 关掉「限制工作区」危险吗？

它只扩大可访问路径范围；Hard Deny、写入、联网和删除开关仍然独立生效。建议仅在确有需要时关闭。

### Stop 之后改动会回滚吗？

不会。Stop 只保证发送中断信号，已经由外部命令产生的副作用不会自动回滚。重要仓库请使用版本控制。

## 数据

### 数据存在哪里？

桌面版数据库位于 `~/Library/Application Support/Atolla/data/atolla.db`，日志位于同目录下的 `logs/`。

### 可以用 MySQL 吗？

可以。在设置页验证 MySQL 连接后即可迁移数据并切换驱动。
