## 概览

数字员工每一次有副作用的动作——写文件、联网、执行命令、删除——都要先经过**权限网关**。网关按固定优先级给出三种结论之一：**ALLOW（允许）**、**DENY（拒绝）** 或 **REVIEW（人工复核）**。需要你决定时，电脑、手机和灵动岛会同时提示。

## 权限网关的五道关卡

```text
引擎准备调用工具
        ↓
Hook / 工具事件 → 规范化 ToolAction
        ↓
① Hard Deny → ② 员工权限 → ③ 安全只读规则
        ↓
④ 当前会话精确授权 → ⑤ JEV 自动审核
        ↓
ALLOW / DENY / REVIEW → 写入审计并通过 SSE 更新对话
```

| 关卡 | 作用 |
| --- | --- |
| ① Hard Deny | 平台底线：关机、危险删除等动作**立即拒绝**，任何授权都无法覆盖 |
| ② 员工权限 | 按员工的写入、联网、删除与工作区范围校验 |
| ③ 安全只读规则 | 常规只读动作可以直接放行 |
| ④ 会话授权 | 当前会话中已授权的**完全相同**的规范化命令签名 |
| ⑤ JEV 自动审核 | 员工开启「自动审核」时，由本机 JEV 服务进行多维风险评分 |

无法确认风险或审核服务异常时，结论会**降级为 REVIEW，绝不默认放行**。

## 人工审批的三种决定

| 决定 | 效果 |
| --- | --- |
| 拒绝 | 引擎收到拒绝结果，任务按拒绝继续处理 |
| 仅本次允许 | 只放行当前这一次请求 |
| 本次会话允许 | 保存这条命令的**精确签名**，本会话中完全相同的命令将直接放行 |

> [!IMPORTANT]
> 会话授权**不是通配符**，只匹配相同的规范化命令签名。页面关闭或审批超时**不会自动允许**；Hard Deny 和员工策略已拒绝的动作也不会进入可放行的人工审批。

## 在手机与灵动岛上审批

- 移动端命令卡片会展示命令内容、风险与决定状态，并与电脑端关联**同一条审批记录**；
- iOS 灵动岛把「待审批」作为高优先级状态展示，点击会解锁实例并跳转到对应审批；
- macOS 灵动岛中的审批行可以直接打开管理台对应位置；
- PC 与移动端同时查看不会产生两份任务，**审批决定只允许成功提交一次**。

## JEV 自动审核

JEV 是运行在你本机的命令风险审核服务（默认地址 `127.0.0.1:8017`）：

- 在设置页安装并开启 JEV 常驻，再为员工打开「自动审核」；
- 未决的动作会从破坏性、数据丢失、服务、权限、凭据等维度评分，再由权限网关转换为最终结论；
- JEV 未安装、未开启、超时或响应异常时，**安全降级为人工审批**；
- JEV 只做风险判断，不替代 Hard Deny、员工权限或操作系统权限；安装支持 GitHub Release 与国内镜像。

## 中断与终止

- 任务运行时可以随时 **Stop**：平台保证发送中断信号，但已经由外部命令产生的副作用**不会自动回滚**；
- 时间线会保留已产生的内容，并用最终耗时与状态收口。

更多审计与网络白名单细节，见 [4.2 权限控制与审计机制](/docs/4-2-permissions-audit)。
