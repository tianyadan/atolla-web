## Your computer is the source of truth

| Data | Location |
| --- | --- |
| Agents, chats, messages, approvals, queue, audits | Local database (SQLite by default) |
| Code and files | The agent's workspace, always local |
| Engine accounts and sessions | Managed by each engine CLI |
| Mobile-visible mirrors | Your own relay, partitioned by `instance_id` |

The relay holds only **cache mirrors + a command mailbox**.

## Relay security

### Outbound only

The computer long-polls out for commands and pushes snapshots; **the server never opens a connection to your computer**. No public IP, no inbound ports.

### Two separate passwords

| Password | Created by | Used for | Lifetime |
| --- | --- | --- | --- |
| Site gate password | You, at deploy time | Signing in to the relay site | Long-lived, changeable |
| Instance pairing code | **Your computer** (6 digits + letters) | Register, heartbeat, long-poll, snapshots | Short-lived, rotatable, revocable |

- Both are **stored only as hashes** (the gate password uses bcrypt, cost 12), never in plain text or logs;
- The six-character code is **never generated by the server**;
- Revocation invalidates the old code immediately.

### Brute-force protection and sessions

- Sign-ins are rate-limited per IP with temporary lockouts and uniform error messages;
- Registration is rate-limited too; `RELAY_INSTANCE_BOOTSTRAP_TOKEN` can require a bootstrap token for first registration;
- Sessions use short-lived HS256 JWTs (`RELAY_JWT_SECRET` is required in production);
- Enable `RELAY_TRUST_PROXY` only behind a trusted reverse proxy; otherwise spoofed `X-Forwarded-For` is ignored.

### A restricted action set

The relay can only queue actions registered on the computer; device RPCs are validated against a restricted registry.

## About HTTPS

The relay **doesn't enforce HTTPS** so it can run on `http://IP:port` for LANs and testing.

> [!WARNING]
> Plain HTTP on the public internet exposes codes and content to eavesdropping. Short lifetimes, revocation and rate limits reduce the risk, but we **strongly recommend** TLS via a reverse proxy such as Nginx or Caddy.

## LAN direct security

Off by default, listens only after explicit enablement and pairing, binds private addresses only, never exposes the console API, signs every request with a per-device key (timestamp, nonce, HMAC) and can be revoked anytime. HTTP offers no confidentiality — use trusted networks.

## Local protections

- The desktop Go backend runs on loopback `127.0.0.1:8080`, and `AVATAR_ALLOWED_IPS` defaults to `127.0.0.1`;
- Local image rendering refuses `.ssh`, `.aws`, Keychains and other sensitive folders;
- Database and server credentials are encrypted and never echoed.
